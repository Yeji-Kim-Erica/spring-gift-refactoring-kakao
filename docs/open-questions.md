# 확인 필요 목록

## 로그인과 주문 준비

### Q1 카카오 로그인 정상 흐름

- **현재:** 로그인 화면 URL과 인증 코드 누락 시 오류 응답만 확인했다.
- **질문:** 유효한 카카오 인증 코드로 로그인하면 서비스 로그인 토큰이 반환되는가?
- **관련 스토리:** [U01 방문자의 가입과 로그인](user-stories.md#u01)

### Q2 포인트 충전 목적과 기준

- **현재:** 관리자가 회원의 보유 포인트를 충전한다.
- **질문:** 회원은 어떤 이유로 포인트를 받는가? 관리자는 무엇을 근거로 충전할 포인트를 정하는가?
- **관련 스토리:** [U03 회원의 상품 주문](user-stories.md#u03), [U08 관리자의 회원 포인트 충전](user-stories.md#u08)

## 주문 처리와 실패

### Q3 주문 메시지 길이 확인 시점

- **현재:** 메시지 길이는 재고·포인트를 차감한 뒤 주문을 저장할 때 확인된다.
- **질문:** 재고·포인트를 차감하기 전에 메시지 길이를 확인해야 하는가?
- **관련 스토리:** [U03 회원의 상품 주문](user-stories.md#u03)

### Q4 재요청 처리 기준

- **현재:** 같은 요청을 다시 보내면 별도 주문이 생성된다.
- **질문:** 기존 주문의 재시도와 새로운 주문을 구분해야 하는가?
- **관련 스토리:** [U03 회원의 상품 주문](user-stories.md#u03)

### Q5 동시 주문 동작

- **현재:** 여러 주문이 동시에 들어오는 상황은 아직 검증하지 않았다.
- **질문:** 동시 주문에서도 재고와 보유 포인트가 정확히 차감되고, 부족한 경우 주문이 거절되는가?
- **관련 스토리:** [U03 회원의 상품 주문](user-stories.md#u03)

### Q6 주문 실패 시 재고·포인트 처리

- **현재:** 주문이 생성되지 않아도 재고나 포인트가 줄어든 채 남는다.
- **질문:** 주문 생성에 실패하면 재고와 포인트를 모두 주문 전 상태로 되돌려야 하는가?
- **관련 스토리:** [U03 회원의 상품 주문](user-stories.md#u03)

### Q7 주문 실패 사유 안내

- **현재:** 재고 부족·포인트 부족·메시지 길이 초과가 모두 서버 오류로 응답된다.
- **질문:** 사용자가 원인을 구분할 수 있도록 각각의 실패 사유를 알려 줘야 하는가?
- **관련 스토리:** [U03 회원의 상품 주문](user-stories.md#u03)

## 주문 이후

### Q8 카카오 주문 알림의 수신자와 동작

- **현재:** 주문자 자신에게 ‘선물이 도착했어요’라는 알림을 보내도록 되어 있다. 실제 도착은 확인하지 않았다.
- **질문:** 이 수신자와 문구가 의도한 동작인가? 카카오로 로그인한 회원이 주문하면 알림이 실제로 도착하는가?
- **관련 스토리:** [U03 회원의 상품 주문](user-stories.md#u03)

### Q9 주문 후 관심 상품 유지 여부

- **현재:** 주석에는 주문 후 관심 상품을 삭제하는 단계가 있지만 실제로는 남아 있다.
- **질문:** 주문한 상품은 관심 상품에서 삭제해야 하는가, 계속 보관해야 하는가?
- **관련 스토리:** [U03 회원의 상품 주문](user-stories.md#u03), [U04 회원의 관심 상품 보관과 정리](user-stories.md#u04)

### Q10 주문 당시 가격과 사용 포인트 보관

- **현재:** 주문 당시 상품 가격과 사용 포인트가 별도로 저장되지 않는다.
- **질문:** 상품 가격이 변경된 뒤에도 과거 주문의 가격과 사용 포인트를 확인할 수 있어야 하는가?
- **관련 스토리:** [U03 회원의 상품 주문](user-stories.md#u03)
